Why does Java print 5 instead of 1000?

This visualizer walks through the multiplication exactly as Java evaluates it. The surprise: assigning the result to a long does not make the earlier arithmetic use long.

The puzzle

final long MICROS_PER_DAY =
    24 * 60 * 60 * 1000 * 1000;

final long MILLIS_PER_DAY =
    24 * 60 * 60 * 1000;

System.out.println(
    MICROS_PER_DAY / MILLIS_PER_DAY
);
Every literal here — 24, 60, 1000 — is an int literal. Therefore the multiplication is performed as 32-bit signed int arithmetic.

What overflow does

Java int arithmetic uses two's-complement wraparound. Conceptually, only the low 32 bits are kept.

86,400,000,000 mod 232 = 500,654,080

So the overflowing expression becomes 500,654,080. Only then is that already-wrong value widened to long.

Why the denominator survives

24 × 60 × 60 × 1000 = 86,400,000

86,400,000 fits comfortably inside a signed 32-bit int, so MILLIS_PER_DAY is computed correctly.

500,654,080 ÷ 86,400,000 = 5

Integer division discards the fractional part, so the printed result is 5.

The rule to remember

The type of the destination variable does not determine the type of the arithmetic expression.

Java determines the expression type from its operands. If all operands are int, the arithmetic is int. Put a L on an operand before the overflow occurs so Java promotes the calculation to long. 

final long MICROS_PER_DAY = 24L * 60 * 60 * 1000 * 1000;
final long MILLIS_PER_DAY = 24 * 60 * 60 * 1000;

System.out.println(MICROS_PER_DAY / MILLIS_PER_DAY);
// 1000
